# 别让 AI 学会你

一个会学习玩家走位习惯的二维 Boss 对战游戏。V0.3 支持自由走位、蓄力后松手射击，以及依据过去逃离习惯秘密决定方向的横扫。你先选择逃离方向，光束随后扫来；尝试改变习惯，让它的预测落空。

当前版本先跑通软件：使用键盘控制，在 CPU 上完成行为学习，不需要独立显卡、网络服务或 myDAQ。课程项目后续再接入 NI myDAQ、摇杆、按钮和 LED。

## 安装与启动

开发环境使用已有的 Conda 环境 **`gkc3C`（Python 3.10.18）**。在项目根目录打开终端：

```powershell
conda activate gkc3C
python -m pip install -r requirements.txt
python main.py
```

也可以使用 `python -m adaptive_boss` 启动。若终端尚未配置 Conda 激活，可直接使用该环境的解释器：

```powershell
& 'D:\ProgramData\Anaconda3\envs\gkc3C\python.exe' -m pip install -r requirements.txt
& 'D:\ProgramData\Anaconda3\envs\gkc3C\python.exe' main.py
```

运行依赖为 `pygame-ce`、`numpy` 和 `scikit-learn`；`pygame-ce` 在代码中仍以 `pygame` 导入。

安装依赖后，也可以双击根目录下的 **`run_game.bat`**。它优先使用上述 `gkc3C` 解释器；找不到时尝试通过 Conda 启动同名环境。

## 操作

| 按键 | 功能 |
| --- | --- |
| `WASD` / 方向键 | 自由移动，支持斜向走位 |
| 按住 `J` / `Z`，再松手 | 蓄力后射击，自动瞄准 Boss；短按为轻射 |
| `Space` / `K` | 向当前移动方向冲刺；未移动时沿最近朝向冲刺 |
| `Enter` | 开始游戏 / 暂停时继续 / 结算后再来一局 |
| `Esc` | 局内暂停；暂停或结算时返回主菜单 |
| `Esc`（主菜单） | 退出游戏 |
| `R` | 局内、暂停或结算时重开 |
| `M` | 开关声音 |
| `C` | 切换固定策略 / 学习策略；主菜单仅切换选择，局内切换并重开 |

菜单、暂停和结算界面的按钮也支持鼠标点击。普通移动没有轨道限制，斜向移动与直线移动速度相同。冲刺沿按下时的移动方向执行，支持斜向；静止时沿最近朝向冲刺。各方向的冲刺速度和持续时间相同，冲刺开始后方向固定，期间短暂无敌，使用后需要等待冷却。

蓄力约 0.9 秒达到上限，期间移速降为正常的 70%；松手时发射一枚子弹，继续按住不会自动连射。冲刺会取消当前蓄力，需要松开攻击键再重新按住。暂停、切出窗口和离开对局也会取消蓄力，避免恢复时意外开火。

## 玩法与 AI

Boss 有 **2400 点生命**，交替使用**定点轰击**与**习惯横扫**。每轮先瞄准约 0.8 秒，预警跟随玩家；锁定时确定攻击位置，并依据该技能此前的完整观察冻结预测和策略。锁定后留出约 **0.45 秒**行动时间，只有生效中的危险区造成伤害。

- **定点轰击**：锁定圆心后轰击，再进行一次单独预警的延迟追击。追击位置也在锁定时冻结。
- **习惯横扫**：瞄准光束指向玩家，锁定瞬间秘密选择顺时针或逆时针；玩家先逃，实际光束再按冻结方向横扫，缓起后加速追赶。横扫持续 **1 秒**，转过 **3.5 弧度（约 200°）**，光束宽 **48 像素**。预警没有旋转箭头或终点轨迹，侧栏在瞄准、锁定和横扫期间隐藏本轮策略与预测概率；起火后只显示当前真实光束，攻击结束后才公开预测结果。横扫后直接进入破绽，没有延迟追击。

一轮攻击全部结束后，Boss 暴露约 **1.4 秒**破绽。轻射基础伤害 **3**，满蓄基础伤害 **42**。装甲阶段，低于 **50% 蓄力**的子弹完全弹开并显示“弹开”，不扣血；达到门槛的子弹造成基础伤害的 **28%**。破绽阶段没有该蓄力门槛，伤害为基础的 **165%**。利用走位躲避，在破绽期开火更有效。Boss 的可见底盘阻挡角色穿行，不造成接触伤害。锁定、追击预警、破绽开启和满蓄力分别有声音提示，可按 `M` 静音。

两种模式使用相同的基础战斗规则：

- **固定策略**：Boss 随机选择策略方向，不使用模型预测。系统仍采集真实走位、训练模型并评估预测，便于观察和对比。
- **学习策略**：该技能积累至少三条完整响应，且预测置信度达到 0.38 时，Boss 使用预测选择横扫方向或轰击追击位置；未满足条件时随机选择。横扫仅使用 `cw` / `ccw` 预测，预测为 `stay` 时也随机选边。两种模式的伤害、阶段时长和移动速度相同。

轰击与横扫各有一个独立模型，分别积累历史、训练和评估。轰击预测五类响应，横扫仅预测 `cw`、`ccw`、`stay` 三类，其概率在这三类之间分配。AI 学习相对 Boss 的实际移动，普通走位与成功执行的冲刺都参与采样：

| 标签 | 轰击模型 | 横扫模型 |
| --- | --- | --- |
| `cw` | 主要顺时针绕行 | 锁定后首先明显向顺时针逃离 |
| `ccw` | 主要逆时针绕行 | 锁定后首先明显向逆时针逃离 |
| `in` | 主要向 Boss 靠近 | 不作为横扫标签 |
| `out` | 主要远离 Boss | 不作为横扫标签 |
| `stay` | 采样窗口内基本停留 | 起火前未明显选边，可包含径向移动，并非完全静止 |

模型在 CPU 上运行。启用后，预测概率由 75% 的近期平滑频率与 25% 的在线逻辑回归结果组成；逻辑回归使用 `scikit-learn` 的 `SGDClassifier(loss="log_loss")`，输入为锁定瞬间的六项游戏状态和该技能最近三次已完成响应。每条新响应将旧的近期计数乘以 0.72，使新习惯能逐步替代旧习惯。连续几次在同一技能前重复一种走位就能形成偏向，改变走位后也能逐步更新。

一次学习按以下顺序发生：

1. 瞄准阶段只跟踪位置；锁定瞬间，使用此前的信息冻结状态、预测概率、策略方向和攻击位置，随后才开始记录本轮响应。
2. **轰击**从锁定持续采样到轰击及追击结束，累计实际径向、切向移动分量。实际路程不足 18 像素时记为 `stay`，否则选择累计移动分量最多的方向；来回移动不会仅因首尾位置重合就被当作停留。
3. **横扫**只在锁定后、光束起火前记录选边：累计实际切向净位移，首次达到正或负 20 像素时冻结 `cw` 或 `ccw`；起火前未达到门槛则为 `stay`。后续反向躲避和看到光束后的补救移动不会改写这次选择。
4. 整轮攻击结束后，先用真实标签检验锁定时冻结的预测，再训练对应技能的模型。未执行的冲刺、贴墙时未发生的移动都不会制造样本；战斗结束时未完成的窗口不参与训练。

预测和策略只使用决策前已发生的信息，不读取未来输入；进入锁定后，攻击计划不会因为后续走位而改变。每局重置模型和统计，从头学习。

可以先在几次横扫锁定后都顺时针逃离，再改为逆时针，观察每轮结束后的预测结果。预测正确也不代表实际光束一定命中。侧栏区分当前技能观察数与全局总观察数，近期准确率为该技能最近 20 次预测；结算使用两个模型的全局统计。横扫实际命中与轰击追击命中分别统计；方向预测统计排除 `stay`。日志中的历史多数类基线只使用该技能此前的累计标签，用于和快速适应的模型比较。

## 开发与验证

安装开发依赖并运行测试：

```powershell
conda activate gkc3C
python -m pip install -r requirements-dev.txt
python -m pytest
```

常用启动参数：

```powershell
python main.py --mode adaptive --seed 7
python main.py --mode fixed --mute
python main.py --headless --smoke-test --screenshot runs/smoke.png
```

`--mode` 选择初始模式，`--mute` 关闭音效，`--no-logs` 禁用对局日志。`--seed` 固定游戏中的随机数起点，便于在相近条件下调试；玩家输入和操作时机会影响结果，种子相同不代表两局会完全一致。

`--headless` 用于无窗口运行，必须与 `--smoke-test` 一起使用。自动演练执行移动、蓄力射击与冲刺，运行完成后退出；配合 `--screenshot` 保存调试画面。自动演练的模拟时间不等于实际等待时间。

## 代码与记录

| 路径 | 用途 |
| --- | --- |
| `main.py` | 启动入口 |
| `run_game.bat` | Windows 双击启动入口 |
| `adaptive_boss/app.py` | 游戏界面、菜单与主循环 |
| `adaptive_boss/engine.py` | 战斗状态与碰撞、预警、冲刺和响应采集 |
| `adaptive_boss/input.py` | 键盘状态与游戏输入转换 |
| `adaptive_boss/learning.py` | 在线预测、学习和评估统计 |
| `adaptive_boss/audio.py` | 音效生成与播放 |
| `adaptive_boss/telemetry.py` | 每局 JSONL 记录 |
| `adaptive_boss/pilot.py` | 仅根据可见预警操作的自动演练输入 |
| `tests/` | 核心逻辑测试 |
| `requirements.txt` | 运行依赖 |
| `requirements-dev.txt` | 开发与测试依赖 |
| `runs/` | 自动生成的每局 JSONL 记录与调试截图，不纳入 Git |

每局默认生成一份 `runs/session_*.jsonl`，每行是一个 JSON 对象。V0.3 使用 `schema_version: 3`，保留会话信息、锁定时冻结的决策、整轮结束后的真实响应与预测结果、阶段变化、射击、冲刺、双方受击、装甲弹开和结束摘要。`boss_block` 只表示装甲完全挡住子弹，保留命中位置与蓄力比例，不计为 `boss_hit` 或伤害。可用于比较模式和整理课程实验数据；记录时间使用 UTC。模型当前不跨局保存，重新开始会保留已有日志，并启动一份新记录。

分析时可以通过 `attack_id` 关联 `decision`、`observation`、`phase` 与 `player_hit`，以 `attack_kind` 区分 `bomb` / `sweep`。`observation.correct` 表示预测是否正确；`player_hit.is_counter` 表示是否被轰击的后续追击实际击中，`using_prediction` 表示该轮是否应用了学习策略。`response_rule` 区分轰击的 `whole_window` 与横扫的 `first_escape`。

结束事件中的 `counter_hits / counter_attempts` 是轰击追击的命中数与生效次数；`sweep_hits / sweep_attempts` 单独统计横扫。对应的 `adaptive_counter_*` 和 `adaptive_sweep_*` 仅统计应用预测的回合。分母为零时不计算命中率。会话结束摘要同时保存全局与分技能学习统计，避免把预测猜中与实际命中混为一谈。

会话中的 `input_source` 区分 `keyboard`（真人键盘操作）与 `smoke_test`（自动演练）。整理真人对照实验时，仅选用 `keyboard` 记录，避免混入测试程序的操作。

输入通过 `InputState` 与战斗逻辑分离。后续接入 myDAQ 时，可将摇杆和按钮读数转换为相同的输入状态，复用现有游戏和学习模块；本版不安装 NI-DAQmx 驱动，也不读取硬件。
